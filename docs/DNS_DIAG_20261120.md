# DNS roto en el móvil (bloquea descargas, apt, NetHunter y ADB por IP)

> Hallazgo del 2026-11-20, medido en el S21 Ultra mientras instalaba NetHunter.
> **Síntoma**: `pkg install` → *"None of the mirrors are accessible"*; `wget`/`apt` fallan;
> `python3 -c "socket.gethostbyname('gitlab.com')"` → `socket.gaierror: [Errno 7] No address
> associated with hostname`. Pero el móvil **sí** navega (el túnel Cloudflare del maestro
> funciona) y **las apps del sistema sí tienen red**.

## 1. Medición

| prueba | resultado |
|---|---|
| `ping kali.download` **como root** | ✅ resuelve → 104.17.253.239 |
| `socket.gethostbyname('gitlab.com')` **como root** | ✅ |
| `socket.gethostbyname('gitlab.com')` **como Termux (u0_a622)** | ❌ `Errno 7` |
| DNS directo a 1.1.1.1 / 8.8.8.8 / 9.9.9.9 (UDP/53) **desde Termux** | ✅ resuelven (`gitlab.com` → 172.65.251.78) |
| TCP a 1.1.1.1:443, 8.8.8.8:53, 104.16.132.229:443 **desde Termux** | ✅ |
| `getprop net.dns1 net.dns2` | **vacío** (tras `setprop`: 1.1.1.1 / 8.8.8.8, pero **no** cambia nada) |
| `cmd netd resolver setdns/getdns <netid>` | **sin salida** (no disponible en este ROM) |
| `settings get global private_dns_mode` | `null` (Private DNS no es el culpable) |

## 2. Redes presentes

```
network{102}  rmnet4  (LTE)  DnsAddresses: 86.104.186.208, 86.104.186.209   VALIDATED
network{107}  wlan0          DnsAddresses: 192.168.1.1 (el router)
tabla dummy0: default dev dummy0            ← la VPN
ip rule: fwmark 0xc0000/0xd0000 lookup legacy_system, y reglas por uid
```

⇒ La **VPN** (interfaz `dummy0` + reglas por `fwmark`/`uid`) se lleva todo el tráfico y **no
aporta servidor DNS**; netd no tiene a quién preguntar para los uids de las apps ⇒ error 7.
El contexto de **root** (magisk) sí sale por una vía con DNS.

## 3. Por qué importa

- `apt`/`pkg` de Termux: **inoperable** ⇒ no se puede instalar `proot`, ni nada de Kali.
- Descarga del rootfs de NetHunter: imposible por nombre (sí por IP).
- `adb connect`/pairing: el nombre del host no resuelve.

## 4. Soluciones

### 4.1 En la app VPN (acción del usuario, la correcta)
Activar **"DNS a través de la VPN"** o poner **DNS manual 1.1.1.1 / 8.8.8.8** en la conexión.
→ netd recibe un DNS del servidor VPN y todas las apps resuelven.

### 4.2 Sin tocar la VPN: descarga por IP (workaround, ya implementado)
Resolver el nombre con un DNS público (consulta UDP/53 directa, que **sí** funciona) y
descargar por IP con la cabecera `Host`:
```bash
IP=$(resolver_con_dns_public kali.download)
wget --no-check-certificate --header="Host: kali.download" \
     "https://$IP/nethunter-images/current/rootfs/$IMG" -O "$IMG"
```
Implementado en `tools/nh_chroot_install.sh` (usa `--no-check-certificate` porque el certificado
no valida contra la IP).

### 4.3 DNS propio dentro del chroot
Un chroot/proot puede llevar su **propio `/etc/resolv.conf`**:
```
nameserver 1.1.1.1
nameserver 8.8.8.8
```
Con eso, **dentro de Kali** la resolución funciona aunque el sistema no resuelva.

### 4.4 `setprop net.dns1/net.dns2`
**NO funciona** en Android 10+: netd ignora las props globales y usa el DNS por interfaz.
(Comprobado: seeglob las props, la resolución sigue fallando.)
