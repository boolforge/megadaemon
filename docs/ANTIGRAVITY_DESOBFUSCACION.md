## 1. Qué es el binario (medido)

| Magnitud | Valor |
|---|---|
| Ruta | `/workspace/agy-re/liblanguage_server.so` |
| Bytes | **181.358.800** |
| Formato | ELF64 **AArch64**, little-endian |
| Lenguaje | **Go 1.28** (sin DWARF) |
| Símbolos dinámicos | **558** (sólo del runtime ⇒ **stripped**) |
| `pclntab` | offset de fichero **`0x1449ff0`**, 161.682 funciones, **161.682 nombres resueltos** |
| Primer `PT_LOAD` | `vaddr 0x0` ⇒ **dirección en runtime = bias + VA del ELF** |

**Consecuencia directa**: no hay PLT/GOT que parchear (Go llama a sus
funciones con `BL` directos) y Go hace la E/S de red con syscalls crudas
⇒ **los ganchos de libc del payload no disparan contra este binario**.
La única forma de interceptarlo es hookear **funciones Go**, y para eso
el `pclntab` es la herramienta (ya es dependencia del daemon:
`go-retool`).

## 2. LA VERDAD DE LAS DIRECCIONES (y el error que casi nos come)

El corpus de Ghidra (`tools-out/todo/s{0,1,2}/`) **NO** comparte espacio de
direcciones con el `pclntab`:

| Fuente | `text.(*Decoder).consumeToken` |
|---|---|
| `pclntab` (verdad) | `0x4f9f518` |
| Índice de Ghidra | `0x509f518` |

⇒ **El índice de Ghidra está `+0x1000000` (1 MiB) por encima** del pclntab
en 18.268 de 19.595 funciones emparejadas por nombre (**93 %**).

**Regla**: la dirección buena es la del **`pclntab`** (`go-retool`), porque la
tabla la escribe el propio enlazador de Go. Cualquier plan de hooks hecho
con direcciones sacadas del pseudocódigo de Ghidra **apunta 1 MiB
equivocado** (y a la función de al lado, que es peor que no hookear nada).

`tools/regenerar-go/regenerar.py` no suffers este error: une el TSV con el
índice **por (fichero, línea, nombre)**, no por dirección.

## 7. Los puntos de intercepción (medidos sobre el mapa de símbolos)

Con el `pclntab` se localizan las funciones exactas. Estas seis son las que
importan para "megadaemon en medio":

| Función | VA (ELF) | Para qué |
|---|---|---|
| `codeassistclient.(*CodeAssistClient).GenerateContentFromAICode` | `0x66a2f78` | **la petición del modelo** |
| `codeassistclient.(*CodeAssistClient).StreamGenerateContentFromAICode` | `0x66a27f8` | la petición en streaming |
| `codeassistclient.getAICodeURL` | ver plan | **la URL que se va a usar** |
| `gateway.ParseEnvOverrides` | `0x6d92c28` | `AGY_LLM_GATEWAY_*` |
| `gateway.LoadEffectiveSettings` | `0x6d938e8` | `admin_settings.json` |
| `gateway.(*AuthProvider).getLastDiscoveredCatalog` | `0x6d94448` | **el catálogo descubierto** (Tier 3) |

**Cómo se montan** (`rust-core/src/antigravity_intercept.rs`):

1. MegaDaemon resuelve los objetivos con el `pclntab` y calcula la
   **dirección absoluta** = bias (de `/proc/<pid>/maps`) + VA.
2. Escribe el plan (JSON) en `/data/local/tmp/megadaemon/hooks-plan.json`.
3. El **payload de frida-gum** (`crates/hooks-payload`, bindings oficiales
   de Frida) lee el plan y hace `Interceptor::attach` en cada dirección:
   **loguea masivamente y deja pasar el `.so` real** (Frida no altera el
   flujo mientras nadie cambie el retorno).
4. La **sustitución** va en dos sitios:
   * `tarea = "sustituir_url"` ⇒ el retorno de `getAICodeURL` (una `string`
     de Go: puntero + longitud) se sustituye por la URL del gateway ⇒
     **el LS habla con MegaDaemon**;
   * el **cuerpo** de la petición se reescribe en el gateway (nivel HTTP),
     que es donde se cambia el modelo real (MiniMax), la cuota y el prompt.
