# RESCATE 2026-11-22 — Runbook de recuperación de MegaDaemon

Este documento es el **runbook único**: qué se rompió, por qué, cómo se
recupera y cómo se queda recuperado **sin pasos manuales**. Todo lo que hay
aquí está **medido** (fecha 2026-11-21/22) o marcado `NO VERIFICADO`.

## 2. El punto de entrada único

Un solo fichero, los dos caminos, detecta el entorno:

```sh
# EN EL MÓVIL (Termux, SIN PC)
curl -fsSL https://raw.githubusercontent.com/boolforge/megadaemon/main/deploy/instalador-megadaemon.sh -o instalador.sh
sh instalador.sh --diagnostico     # sólo lee, no toca nada
sudo bash instalador.sh --instalar  # arregla (sudo bash, NO `sudo su <script>`)
```

Qué hace, en orden (todo con verificación y rollback):

1. **Descarga el ARM64** con la URL estable `releases/latest/download/<asset>`
   (**sin API y sin cuota**: 206/200 medidos), verifica el **sha256 contra el
   `.sha256` oficial**, comprueba que es **ELF aarch64**, instala con
   `chmod 755` **antes** de arrancar y **restaura el anterior** si el daemon
   no levanta.
2. **Unifica la credencial** en el `state_dir` real del daemon.
3. **Limpia procesos basura por evidencia**: nuestras tools de una sola
   ejecución atascadas, `cloudflared` sobrantes y `megadaemon-core`
   duplicados. **Nunca** mata a un ascendiente del script (matar al padre
   tumba la sesión de Termux).
4. **Instala el trío de Magisk `service.d`** (supervisor + `cloudflared` +
   watchdog) ⇒ el móvil **levanta solo** tras cada reinicio, **sin Termux**.
5. **Escribe la URL canónica en los 3 sitios**: `<state_dir>/tunnel.url`,
   `/data/local/tmp/megadaemon/tunnel.url` y `/sdcard/megadaemon.url`.
6. **Publica la URL viva al repo** (`state/channel.json`) si encuentra un
   token de escritura en `/data/local/tmp/megadaemon/.gh_token` (0600).
7. **DuckDNS desde el móvil**: su IP pública **es** la de casa ⇒ el móvil
   puede ser el único escritor del A record, y lo **verifica por DoH** (un
   `OK` de la API no prueba nada: sólo gestiona subdominios ya registrados).
8. **Parche CSC en Rust** (`megadaemon-core csc list|set|matrix|inventory`):
   cualquier valor, cualquier feature, cualquier CSC, y comparación de los
   CSC del firmware. **Sin Python en el móvil**.
9. **Verificación real**: `/health` en 4 puertos y `POST /mcp tools/list`
   contando herramientas.

Opciones: `--diagnostico` · `--instalar` · `--selftest` · `--build` (ARM64
desde fuente con NDK) · `--csc-valor=` · `--purgar-antigravity` ·
`--sin-publicar` · `--movil` / `--pc` · `--serie=`.

## 3. La flota entra (medido el 2026-11-21 23:52)

```
URL viva : https://graphical-subscriber-sys-oil.trycloudflare.com
/api/status           -> 200 (sin credencial)
POST /api/session/exchange -> {"ok":true,"auth_token":…}   (key de la flota)
POST /mcp tools/list  -> 26 herramientas
root_exec             -> uid=0(root) context=u:r:magisk:s0
```

Cliente para la flota: `tools/md_mcp.sh <herramienta> '<args json>'`
(`list` para el catálogo, `raw <ruta>` para GETs).

**Auto-recuperación**: si el canje falla con la URL guardada, `md_mcp.sh`
lee `state/channel.json` del repo, prueba sus URLs contra `/api/status` y
persiste la que responde. El hostname del túnel rápido cambia en cada
reinicio ⇒ sin esto la flota cree que el móvil está caído.

## 4. Matriz de recuperación (síntoma → causa → arreglo)

| Síntoma | Causa | Arreglo | Comando |
|---|---|---|---|
| 404 bajando el binario | tag `latest` inexistente | URL estable | `sh instalador.sh --instalar` |
| Móvil con 0 puertos | supervisor muerto (Termux) | `service.d` | `sudo bash instalador.sh --instalar` |
| 403 para toda la flota | key no está en el `state_dir` real | unificar credencial | ídem |
| `quick` vacío | URL en el dir equivocado | 3 sitios | ídem |
| Dominio apunta al datacenter | A record publicado desde el sandbox | A record **desde el móvil** | ídem |
| CI rojo sin binario | ANSI en el log + LTO/OOM | gate saneado | `tools/ci-suite.sh rust-core` |
| La flota "no ve" el móvil | hostname nuevo | auto-recuperación | `tools/md_mcp.sh list` |
